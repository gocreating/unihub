# Implementation Plan: Legacy Finance Data Migration

**Branch**: `003-legacy-data-migration` | **Date**: 2026-05-21 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/003-legacy-data-migration/spec.md`

## Summary

A standalone Python script (`data_migration/migrate.py`) that reads 10 legacy
CSV files and produces 5 unihub-importable CSVs in `data_migration/unihub-ready/`.
The script filters out tables with no unihub equivalent (portfolios, transactions,
securities), resolves NanoID foreign keys to human-readable currency codes, and
rounds float exchange rate values to 6 decimal places. Output can be imported
directly via unihub's Import flow with zero errors expected.

## Implementation Approach

### Script: data_migration/migrate.py

**Algorithm**:

1. Build asset reference map from `finance_asset.csv`:
   ```
   asset_map = {reference: code}  # e.g., {"yRLSZ6Vt": "TWD"}
   ```
   Include all assets (settleable and non-settleable) so that any FK in the
   exchange rate or account tables can be resolved without filtering prematurely.

2. Write `finance_currency.csv` from assets where `is_settleable == "true"`:
   ```
   code, name, symbol
   ```

3. Write `finance_account.csv` from all legacy accounts:
   ```
   id (reference), name, currency (resolve via asset_map), open_datetime, close_datetime
   ```

4. Write `finance_balancesheet.csv` from all legacy balance sheets:
   ```
   id (reference), date (balanced_time)
   ```

5. Write `finance_balance.csv` as header-only:
   ```
   id:string, account_id:string, balance_sheet_id:string, amount:decimal
   ```

6. Write `finance_exchangerate.csv` from all legacy prices:
   ```
   id (reference), base_currency (resolve), quote_currency (resolve), rate (rounded), date (confirmed_time)
   ```

**Decimal rounding**: Use `Decimal(str(float_value)).quantize(Decimal('0.000001'))`.

**Output header format**: Exact match to unihub export template headers
(e.g., `id:string,name:text,currency:string,open_datetime:datetime,close_datetime:datetime`).

**Error handling**: If an `*_reference` FK cannot be resolved via `asset_map`,
abort with a descriptive error message identifying the offending row.
