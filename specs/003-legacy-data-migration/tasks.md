**Prerequisites**: plan.md ✅ spec.md ✅ research.md ✅ data-model.md ✅ quickstart.md ✅

**Tests**: Not requested — verification is manual row count + unihub import check.

**Organization**: Tasks are grouped by user story to enable independent validation
at each checkpoint.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no blocking dependencies)
- **[Story]**: Which user story this task belongs to ([US1], [US2])

## Dependencies & Execution Order

### Phase Dependencies

- **Setup (Phase 1)**: No dependencies — start immediately
- **Foundational (Phase 2)**: Depends on T001 (script file exists)
- **User Story 1 (Phase 3)**: Depends on Phase 2 (T003)
- **User Story 2 (Phase 4)**: Depends on Phase 3 checkpoint (currencies written, `main()` wired)
- **Polish (Phase 5)**: Depends on Phase 4 completion

### User Story Dependencies

- **US1 (P1)**: No story dependencies — only needs `build_asset_map()` from Phase 2
- **US2 (P2)**: Requires US1 complete (currencies must exist in unihub before accounts import)

### Within Each User Story

- T006, T007, T008 can run in parallel (different functions, no shared state)
- T009 depends only on `asset_map` (can start after T003, does not need T006–T008)
- T010 (wiring + verification) must come after T006–T009

### Parallel Opportunities

- T001 and T002 can run in parallel (different files)
- T006, T007, T008 can run in parallel within Phase 4
- T011 (ruff) can run in parallel with T012 (import verification)
